# 建模分析与审查质检清单

`建模分析与审查` 在审查真人建模手队友交付物、判断是否可以进入编程实现之前，逐项完成以下检查。

> 语言路由不在此阶段完成最终确认（路由由编程手在编程手阶段依据 `references/roles/编程手核心/references/语言路由指南.md` 自行判定）。但本清单会检查“路由客观输入”是否已提供（未提供则由编程手独立推导）。

---

## A. 前置合同检查

- [ ] **核心结论清晰**：能用一句话写出本题要解决的核心问题
- [ ] **子问题拆解完整**：核心结论已按证据链拆解为数量适当、各自承担独特任务的子问题；2-4 个仅作常见参考，不得为满足数量强行拆分或合并
- [ ] **模型映射完整**：每个子问题有对应的模型负责
- [ ] **防冗余已检查**：没有两个模型重复验证同一层面的信息
- [ ] **备选方案已记录**：每个模型都记录了备选方案
- [ ] **路由客观输入**：若建模手提供，须审查其正确性（算法类别是否匹配、数据规模是否属实、所需库是否必要充分）；若未提供，编程手须独立推导路由（不退回、不凭偏好），详见 `references/roles/编程手核心/references/语言路由指南.md` 路由审查与独立推导规范

## B. 模型选择检查

- [ ] **理论依据充分**：所选模型的适用性依据可追溯；经典模型可记录教材或标准参考书，改进模型、特殊公式和创新声明应补充论文或对比证据
- [ ] **数据适配性确认**：所选模型与题目提供的数据格式、体量匹配
- [ ] **复杂度评估**：所选模型的复杂度在可接受范围内
- [ ] **创新性确认**：创新是加分项，不得为了新颖替换适用的经典模型或堆砌复杂模型
- [ ] **三原则遵守**：能用初等方法不用高等方法；能用简单方法不用复杂方法；能用更多人看懂的方法不用少数人才能看懂的方法

## C. 算法设计检查

- [ ] **求解步骤完整**：从输入到输出的每一步都有清晰描述
- [ ] **边界条件处理**：异常值、缺失值、极端情况有对应策略
- [ ] **评价指标明确**：模型优劣的评判标准已定义
- [ ] **参数设置合理**：关键参数有取值范围和调整方法

## D. 交付文档检查

- [ ] **前置合同已填写**：可附在分析文档开头，或作为合并交付物中的独立章节
- [ ] **分析文档完整**：包含问题分析、模型选择、算法设计、数据要求等必要内容；文件名和拆分形式不作硬性要求
- [ ] **术语表已建立**：中英文对照、符号定义完整；可独立成文件，也可合并在完整交付物中
- [ ] **编程手交接项清晰**：
  - 模型公式与推导 ✓
  - 算法步骤与伪代码 ✓
  - 可视化需求清单 ✓
  - 模型选择依据与参考依据 ✓
  - 术语表 ✓
  - 图表清单 ✓
- [ ] **参考依据已记录**：根据模型类型记录教材、标准参考书、论文、公式来源或对比证据；不要求所有经典模型都必须单独搜索论文

## E. 风险检查

- [ ] **模型局限性已记录**：每个模型的假设条件和局限性已说明
- [ ] **数据敏感性已评估**：数据质量问题对结果的影响已分析
- [ ] **失败预案已准备**：首选方案失败时，备选方案和切换条件已明确

## F. 准入灯号检查

- [ ] 已给出题目级绿灯/黄灯/红灯结论
- [ ] 已区分阻断项与非阻断缺口
- [ ] 已明确题目级结论与子问题级结论的关系
- [ ] 黄灯结论已写明放行条件、责任人、补充时点和关闭标准
- [ ] 红灯子问题未被标记为可开始编程

## G. 逐子问题准入检查

- [ ] 每个子问题都有独立准入灯号
- [ ] 每个子问题的输入和输出明确
- [ ] 关键公式、变量和约束可计算
- [ ] 所需数据缺口已标记为通过、待补或阻断
- [ ] 算法步骤可复现
- [ ] **至少2种**结果验证方式可执行（来自不同类别A/B/C/D：A复算类/B替代算法类/C边界极限类/D外部对照类，定义见编程手核心工作流程第五节）
- [ ] 每个黄灯子问题都有明确放行条件
- [ ] 每个红灯子问题都有暂停或退回原因

## H. 交接契约与问题闭环检查

- [ ] **题目要求追踪矩阵已填写**：每个小问、约束和输出要求都有模型响应、输出证据和状态
- [ ] **问题已编号并可追踪**：每条问题都有影响子问题、严重级别、是否阻断、责任人和修复时点
- [ ] **关闭标准已定义**：每个阻断项或高风险项都有可验收的关闭条件
- [ ] **变量-数据映射完整**：每个模型变量都能对应数据字段或明确推导式
- [ ] **单位与维度明确**：变量单位、标量/向量/矩阵维度、索引范围和时间/空间粒度已记录
- [ ] **缺失与异常策略明确**：缺失值、异常值和不可得数据的处理限制已记录
- [ ] **上下游接口明确**：输入来源、输出文件/格式和接收子问题已记录
- [ ] **路由事项标注为待确认**：审核手只核验路由客观输入，不把推荐语言当作最终路由结论
- [ ] **语言统一伪理由已排除**：当推荐理由中出现“全题统一语言”“与某题保持一致”等表述时，必须回溯每个子问题的独立路由结论，禁止用“语言统一”掩盖客观不匹配（例：题一已路由 MATLAB、题三却以“与题一一致”推 Python，自相矛盾）
- [ ] **可视化中文渲染已列为核验项**：凡涉及 matplotlib / MATLAB 出图且交付需中文标注的子问题，其“中文字体正常渲染”必须作为显式待核验项列入执行清单，不得默认通过或仅在目标中描述
- [ ] **“已安装/零依赖”未越位为决定性依据**：当子问题客观为“均可”或 MATLAB 本更优时，路由表不得用“Python 已安装零依赖”单边压向 Python；该理由仅可作并列便利项
- [ ] **性能/复杂度数字有依据**：路由表中出现的运行时间、复杂度、规模阈值等具体数字，必须标注来源或明确“估算”，不得凭印象写无出处的具体数值
- [ ] **“均可”题倾向方已限定场景**：若推荐“均可”但给出倾向方，其理由须限定生效场景（如仅扩展规模时成立），主场景仍标纯“均可”，不得让读者误判主场景偏置
- [ ] **MATLAB 预检误判已排除**：路由表中 MATLAB 工具箱函数不得以 `exist()==0` 误判为“缺失”，也不得以 `which` 有路径即误判“独立函数可用”；对象方法（如 bodeplot/stepplot/pzplot/pidtune）须经 `which('-all')` 路径 + 最小可运行调用（`sys=tf(...)` 实测）双层验证才记为可用（见编程手通用避坑与验证规范第七节补充）

## I. 报告定版与复审检查

- [ ] **报告元数据完整**：题目名称/题号、审查日期、输入材料清单和版本已记录
- [ ] **审查边界明确**：审查范围和未审查范围已记录
- [ ] **报告版本明确**：初审为 `v1.0`，补充或复审递增版本号，不覆盖旧报告
- [ ] **复审记录完整**：修订材料版本、已关闭问题、复审结论、仍开放问题和新版本已记录
- [ ] **模型类型验证已匹配**：根据优化、预测、评价或仿真类型填写对应验证矩阵
- [ ] **验证缺口已进入准入判断**：阻断性验证缺失不得标绿灯，非阻断缺口须标黄灯或记录限制

## J. 模型类型验证检查

- [ ] **优化题**：已检查可行性、约束回代、目标值重算、整数性及上下界/最优性证据
- [ ] **预测题**：已检查基线、误差指标、残差、时间切分和外推边界
- [ ] **评价题**：已检查指标方向、归一化、权重敏感性和排序稳定性
- [ ] **仿真题**：已检查随机种子、重复次数、不确定性区间和极端情景
