# 设计文档：建模手「审查报告（Word）」功能

- **日期**：2026-07-14
- **状态**：已评审待确认（brainstorming → writing-plans）
- **所属技能**：`math-modeling`（路径 `C:\Users\qingf\.claude\skills\math-modeling`）
- **目标仓库**：`https://github.com/qingfeng-crypto/mathmodel`（已 privatize，源=用户）

---

## 1. 目标（Objective）

为「建模手」角色（现为**审查角色**）新增一项能力：在收到建模手交付的建模资料后，
依据既有审查规范完成审查，并产出一份 **Word 格式的审查报告**，保存到用户桌面，
供用户个人方便查阅，**不进入项目目录、不提交**。

本功能是建模手角色"审查产出"能力的**落地与存档**形态，不是新的审查逻辑。

---

## 2. 背景与动机

- 数模技能已 privatize：建模手 = 审查角色（5 维度），编程手 = 实现 + 语言路由，论文手已移除，源改为 `qingfeng-crypto/mathmodel`。
- 用户希望在手动收到建模手资料后，由 AI 据技能产出"审查报告"，且以 Word 形式存桌面方便自己看。
- 该文件纯属个人便利，**不是需提交的成果**，故保存路径单独指定为桌面，其余工程结构不变。

---

## 3. 设计决策（来自澄清问答）

| 决策点 | 结论 |
|--------|------|
| 生成时机 | **不自动**。用户手动把资料发来，并明确要求出报告；加载技能时先问是否需要资料 |
| 加载行为 | 每次加载建模手技能，第一句必须说：「你好，请问需要提供建模手的资料以此来产出审查报告吗？」 |
| 保存路径 | **固定写死** `C:\Users\qingf\Desktop`（`DESKTOP_REPORT_PATH` 常量） |
| 报告内容 | **标准版 + 可复制修改稿**：审查结论 / 逐项问题清单（含可复制修改稿文本）/ 退回补充项 / 路由客观输入确认 |
| 产出模板 | 将现有两份"产出模板"**合并为单一审查报告结构**，对话结论与 Word 导出共用，消除重复 |
| 生成方式 | 复用现有 `tools/docx`（python-docx） |

---

## 4. 组件设计

### 4.1 加载即问（开场白）— 改 `建模手/SKILL.md`

在 `建模手/SKILL.md` 顶部增加**硬规则**：

> **加载即执行（开场白）**：每次加载本技能，第一句话必须输出：
> 「你好，请问需要提供建模手的资料以此来产出审查报告吗？」
> 用户确认提供资料后进入审查；若用户仅需普通审查对话，则按审查规范进行，不强制出报告。

目的：用户易忘触发点，开场白确保每次都提示。

### 4.2 单一审查报告结构（合并旧模板）— 改 `建模手/SKILL.md` + `建模手/references/工作流程.md`

将以下两份内容**合并为一份**定义，作为唯一权威结构：

- `SKILL.md` 现有「审查输出要求」
- `工作流程.md` 末尾「审查记录模板」

合并后结构（对话结论与 Word 导出共用）：

```
一、审查结论
    - 总体结论：可进入编码 / 需补充 / 有重大风险
    - 已确认风险点
    - 待验证项
二、逐项问题清单
    | 维度 | 问题 | 影响 | 修改建议 | 可复制修改稿 |
    （每行对应一个问题；可复制修改稿 = 可直接粘贴回题目分析.md 的修订文本）
三、退回补充项
    - 需建模手补充的具体内容（如有）
四、路由客观输入确认
    | 子问题 | 算法类别 | 数据规模 | 所需库/工具箱 | 是否齐全 |
```

### 4.3 Word 报告生成步骤 — 改 `建模手/references/工作流程.md`

在审查流程末尾新增步骤「生成审查报告（Word）」：

- **触发**：用户明确要求出报告，且审查已完成。
- **工具**：调用 `tools/docx` 技能（python-docx）生成文档。
- **保存路径**：`DESKTOP_REPORT_PATH = C:\Users\qingf\Desktop`
- **文件名**：`建模审查报告_YYYYMMDD_HHMM.docx`（用当前时间，避免覆盖）
- **内容**：按 4.2 单一结构填充（标准版 + 可复制修改稿）。
- **不落项目目录、不提交**。

伪流程：

```
收到用户"出报告"指令
  → 汇总本次审查结果（结论 / 问题清单 / 退回项 / 路由确认）
  → 调用 tools/docx 生成 .docx
  → 保存到 C:\Users\qingf\Desktop\建模审查报告_<时间戳>.docx
  → 向用户回执：文件完整路径
```

### 4.4 审查方法（复用，不重定义）

以下**既有规范保持不变、被本功能调用**：

- 5 审查维度：逻辑闭环 / 编程可行性 / 公式变量 / 数据可行性 / 术语一致性
- `前置合同.md`：建模交付物验收标准
- `工作流程.md` 审查流程（第零~五步）
- `质检清单.md`：审查检查项
- 路由客观输入齐全性检查

本功能**不新增、不修改**上述审查逻辑，只消费其产出。
