# 建模手「审查报告（Word）」功能 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给建模手（审查角色）新增能力：加载即问开场白、按单一审查报告结构审查、产出 Word 审查报告到桌面（标准版+可复制修改稿），并补全"路由审查与独立推导规范"。

**Architecture:** 纯技能文档（markdown）改造，无代码运行时。改动集中在 `references/roles/审核建模手/` 及其路由审查相关文档。Word 生成复用现有 `tools/docx`（python-docx），不新增脚本。审查"规则"复用既有 5 维度/前置合同/质检清单/流程，仅新增路由审查规范与产出落盘步骤。

**Tech Stack:** Markdown 技能文档；`tools/docx`（python-docx）生成 .docx；保存路径 `C:\Users\qingf\Desktop`。

## Global Constraints

- 加载即问：每次加载建模手技能第一句必须说「你好，请问需要提供建模手的资料以此来产出审查报告吗？」
- 保存路径固定 `C:\Users\qingf\Desktop`，文件名 `建模审查报告_YYYYMMDD_HHMM.docx`；仅落桌面，不写项目目录、不提交。
- 单一审查报告结构：对话结论与 Word 导出共用，不另立第二份模板。
- 路由始终由编程手客观判定：提供则审查正确性、缺失则编程手独立推导（不退回、不盲从）；报告路由不取代逐子问 B 模式确认闸门。
- 不动：项目目录结构、编程手实现逻辑、5 审查维度与审查流程、主 SKILL.md、references/README.md、README.md。

```
## 七、路由审查与独立推导规范

语言路由始终由编程手客观判定，不盲从建模手，也不因缺输入退回或凭偏好。

- **情形一（建模手已提供路由客观输入）**：逐项审查算法类别是否真匹配该子问、数据规模是否属实、所需库/工具箱是否必要且充分；发现错误/不当须纠正并给出依据，不盲从。
- **情形二（建模手未提供路由客观输入）**：不得退回了事，也不得凭偏好猜；回到题目与每个子问，独立分析所需技巧（算法类别、数据规模、数值稳定性、生态工具、上下游接口），依本指南客观推导 Python/MATLAB，并给出至少两条客观理由，照常走用户确认闸门。

> 本规范被建模手审查报告「路由客观输入确认」环节引用：报告须呈现"建模手是否提供 + 编程手审查结论 + 编程手独立推导推荐语言及依据"。
> 与逐子问确认闸门的关系：审查报告第四节给出的语言路由是审查阶段的汇总推荐，不取代编程手阶段既有的逐子问 B 模式确认闸门。编码前仍须对每个子问题再次展示推荐语言、≥2 条客观理由、另一语言可行性与不优先原因，并等用户确认。
```
