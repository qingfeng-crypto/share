# 数学建模三阶段工作指南

本文档介绍数学建模技能中三个阶段的职责、工作流程和协作关系。

---

## 集成的子Skill

本技能集成了四个专业的文档处理子Skill，位于 `tools/` 目录下：

- **`tools/docx`** - Word文档处理
  - 创建、读取、编辑 .docx 文件
  - 生成格式规范的数学建模论文
  - 支持表格、图片、公式等复杂格式

- **`tools/pdf`** - PDF文档处理
  - 读取PDF格式的题目文档
  - 提取文本和表格数据
  - 支持PDF合并、拆分等操作

- **`tools/xlsx`** - Excel表格处理
  - 读取和编辑 .xlsx 文件
  - 处理题目附带的数据表格
  - 指定 Excel 模板时保留结构和公式

- **`tools/paper_search`** - 论文搜索
  - 通过OpenAlex API搜索学术论文
  - 为数学建模论文提供参考文献支持
  - 自动生成标准引用格式
  - 支持摘要重建和多字段搜索

**注意：原 `scripts/` 目录下的Python脚本已被集成到 xlsx skill 中，现在使用 xlsx skill 替代原有的表格处理功能。**

## 第一阶段：审核建模手

审核建模手阶段负责审查真人建模手或前序分析产物，判断其是否足以进入实现阶段。该阶段只负责审查、准入和问题定位，不承担后续代码实现。

### 角色介绍

- **审核建模手**：审查建模交付物，输出审查结论与问题清单（结构见 `roles/审核建模手/SKILL.md`）。
- **下一阶段接收方**：编程手核心基于审查通过的材料继续实现。

**工作输入**：题目文件 + 建模分析报告 + 术语表 + 相关前置材料
**工作输出**：审查结论 + 问题清单 + 准入判断

### 核心职责（建模手审查维度）

| 维度 | 审查内容 |
|------|---------|
| **逻辑闭环** | 模型是否真正回答题目要求，假设是否合理，目标函数与约束是否完整对应问题 |
| **编程可行性** | 每个子问题是否有明确输入、输出、算法步骤，是否可落地实现 |
| **公式与变量** | 公式是否完整可计算，变量是否全部定义，符号是否与术语表一致 |
| **数据与可行性** | 所需数据是否真实存在，计算规模是否在 Python / MATLAB 可承受范围内 |
| **术语一致性** | 术语表是否覆盖全文，中英文对应是否正确，无同名异义 |

### 审查工作流程

> 本阶段聚焦于审查与准入；具体审查细则以 `roles/审核建模手/SKILL.md` 为准。

```
第一步：接收建模材料
    ↓
    核对分析报告、术语表、题目附件是否齐全

第二步：五维度审查
    ↓
    检查逻辑闭环、编程可行性、公式变量、数据可行性、术语一致性

第三步：形成准入结论
    ↓
    输出可进入实现 / 需补充 / 需重做的明确判断

第四步：移交实现阶段
    ↓
    将审查通过材料交给编程手核心继续实现
```

### 问题类型与模型匹配

| 问题类型 | 典型特征 | 推荐模型 | 算法文档 |
|---------|---------|---------|---------|
| **优化问题** | 资源分配、路径规划 | 线性规划、整数规划、图论 | 01-优化算法 |
| **预测问题** | 时间序列、趋势预测 | 灰色预测、ARIMA、LSTM | 02-预测类算法 |
| **评价问题** | 方案选优、绩效考核 | AHP、TOPSIS、熵权法 | 03-评价类算法 |
| **分类问题** | 数据聚类、模式识别 | K-Means、DBSCAN、SOM、GMM | 05-统计分析 |
| **仿真问题** | 系统模拟、风险分析 | 蒙特卡洛、元胞自动机 | 06-综合类算法 |

### 模型选择原则

```
┌─────────────────────────────────────────────────┐
│  建模分析模型选择原则                             │
├─────────────────────────────────────────────────┤
│  1. 高效性：计算速度快、效率高                   │
│  2. 准确性：能准确描述和解决问题                 │
│  3. 简洁性：优先选择相对简单的模型               │
│  4. 创新性：满足适用性、简洁性和可验证性后作为加分项 │
│     不为新颖替换适用经典模型                       │
│  5. 实用性：避免长时间训练的复杂模型             │
└─────────────────────────────────────────────────┘

❌ 谨慎使用：神经网络、深度学习（优先尝试传统方法）
✅ 推荐使用：规划模型、统计模型、评价模型
```

## 第二阶段：编程手核心

编程手核心负责将已审查通过的建模成果转化为可运行代码，并完成验证、结果输出和图表产出。

### 角色介绍

编程手核心阶段负责将建模方案转化为可执行的代码，产出计算结果和可视化图表。

**工作输入**：题目文件 + 审查通过的建模分析文档
**工作输出**：代码文件 + 结果文件 + 可视化图表 + README.md

### 核心原则（必须严格遵守）

**⚠️ 编程语言确认（第一条，必须最先执行）**：
- **在编写任何代码之前，必须先向用户确认使用的编程语言**
- 如果用户未指定，必须按每个子问题的客观条件比较 Python 与 MATLAB，给出推荐及理由后等待用户选择
- **禁止**在未确认编程语言的情况下直接开始编写代码

**遵循你的建模分析文档**：
- **严格按照分析思路**：必须完全按照你在建模分析阶段写出的分析文档中的思路进行代码编写
- **严格使用指定的模型和算法**：必须使用你选择的数学模型和算法，不得自行更换
- **保持一致性**：代码实现应与你的建模分析文档保持完全一致

**超时处理原则**：
- 当代码运行超时时，**加长等待时间**，不要重新写简化的代码

### 核心职责

| 职责 | 具体内容 |
|------|---------|
| **代码编写** | 根据建模文档编写完整可运行的代码 |
| **语言支持** | Python / MATLAB |
| **结果输出** | 确保结果正确输出到文件和终端 |
| **数据可视化** | 生成符合 SCI/Nature 风格的精美图表 |
| **文档说明** | 撰写 README.md 项目说明文档 |

### 工作流程

```
第一步：理解需求
    ↓
    读取：建模分析文档
    路由：逐个子问题客观比较 Python / MATLAB
    确认：等待用户确认后再编码
    理解：题目要求和建模方案

第二步：代码设计
    ↓
    划分：功能模块
    设计：数据结构
    确定：算法实现方法
    规划：可视化图表

第三步：代码实现
    ↓
    编写：结构清晰的代码
    添加：必要的注释
    运行：测试确保正确

第四步：结果验证
    ↓
    确保：结果正确输出
    判断：结果正确性（结合题目、建模文档、运行效果）
    如不正确：进入迭代改进

第五步：迭代改进
    ↓
    如结果不正确：改进代码
    重新运行：验证改进效果
    循环：直到结果正确

第六步：结果输出与可视化
    ↓
    输出：终端打印关键结果
    保存：CSV 文件（不使用 TXT 作为结果总结）
    生成：可视化图表（集成式、3D增强）

第七步：文档撰写
    ↓
    产出：README.md 说明文档
```

### 可视化代码编写原则

**集成式可视化**：
- 可视化代码应与解决问题的主代码一起编写
- 嵌入在数据处理的合适位置
- 运行时可以实时获取数据和画图
- 而不是在运行完成后再单独画图

**3D图表使用**：
- 在合适的场景下使用3D图表以增强视觉效果
- 适用场景：多维数据展示、优化过程可视化、聚类结果展示等

### 可视化约束（重要）

```
┌─────────────────────────────────────────────────┐
│  可视化约束（必须严格遵守）                      │
├─────────────────────────────────────────────────┤
│  ✅  一个图可含多个子图，以"核心结论能一眼读懂"  │
│      为上限，不要为凑数堆砌                      │
│  ✅  常见布局：单图 / 1×2 / 2×2 / 2×3；敏感度    │
│      分析等对比可用 3×3 甚至更大网格            │
│  ✅  多张独立主题的图请分成多个独立图片文件      │
└─────────────────────────────────────────────────┘

正确：plt.subplots(1,2)、plt.subplots(2,2)、plt.subplots(2,3)、plt.subplots(3,3)
错误：为凑数堆砌无关面板，或遮盖某面板后核心结论仍可从其余面板读出（见防冗余原则）
```

**完整可视化规范参见**：`./roles/编程手核心/references/可视化规范.md`（含 Figure Contract、语义调色板、PNG 600 dpi 导出规范；HTML 面板仅作可选扩展参考）

## 第三阶段：交付论文手

交付论文手阶段负责把编程阶段已经产出的代码、结果、图表和说明材料整理为论文协作者可直接接收的材料包。

### 角色介绍

- **交付论文手**：按论文协作需要整理结果、图表、口径说明、文件清单和交付约束。

**工作输入**：代码、结果文件、图表、README、必要的术语和审查结论
**工作输出**：材料包 + 交付说明 + 面向论文协作的结构化清单

### 典型交付内容

```
第一步：收集实现产物
    ↓
    汇总代码、结果表、图表、关键参数说明

第二步：整理论文协作材料
    ↓
    对齐命名、口径、图表说明、结果出处

第三步：输出可交付材料包
    ↓
    供论文手或写作协作者直接接收和使用
```

## 阶段协作

### 信息传递链

```
┌────────────┐    审查结论     ┌────────────┐    材料包      ┌────────────┐
│审核建模手  │ ──────────────> │编程手核心  │ ──────────────> │交付论文手  │
│(审查准入)  │    问题清单     │(代码实现)  │    图表结果     │(交付整理)  │
│            │                 │            │                 │            │
│建模成果输入│                 │实现产物    │                 │论文协作输出│
└────────────┘                 └────────────┘                 └────────────┘
```

### 关键交接点

| 交接点 | 传递内容 | 接收方使用 |
|--------|---------|-----------|
| 审核建模手 → 编程手核心 | 审查结论、问题清单、分析文档、术语表 | 判断可否实现并开展编码 |
| 编程手核心 → 交付论文手 | 代码、结果、图表、README、关键口径说明 | 整理论文协作材料包 |

### 协作要点

1. **术语一致性**：前序术语表应贯穿三阶段
2. **准入先行**：先完成审查准入，再进入实现
3. **交付可复用**：实现阶段产物应便于论文协作者直接接收

## 常见问题

### 审核建模手 FAQ

**Q: 如何选择合适的算法？**
> A: 查看 `assets/README.md` 中的"按题型查找"表格。

**Q: 术语表为什么必须产出？**
> A: 确保三阶段术语一致，提高专业性。

**Q: 必须产出哪些文件？**
> A: `题目分析报告.md` 和 `术语表格.md` 两个文件。

### 编程手核心 FAQ

**Q: 用户未指定编程语言怎么办？**
> A: 按每个子问题的模型、算法、数据规模、工具能力和上下游接口客观比较 Python 与 MATLAB，说明推荐理由、另一语言的可行性和执行方式，等待用户确认后再写代码。不得因为 AI 偏好 Python 或 MATLAB MCP 状态而偏置推荐。

**Q: 子图数量如何把握？**
> A: 不硬性封顶。以"核心结论能一眼读懂"为上限：常见单图 / 1×2 / 2×2 / 2×3，敏感度分析等对比可用 3×3 甚至更大网格；堆砌无关面板或冗余面板（遮盖后仍可读出结论）才应拆分删减。

**Q: 表格文件如何处理？**
> A: 题目输入表格只读不写；普通结果汇总用 CSV；指定 Excel 模板保持结构不变，只填写数据。
