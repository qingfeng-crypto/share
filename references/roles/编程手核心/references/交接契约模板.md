# 交接契约 (Handoff Contract) — 编程手核心 → 交付论文手

本文件定义从 `编程手核心` 向 `交付论文手` 移交的桥梁契约，明确双方责任边界、接受内容、约定条件和回退触发点。

---

## 1. 交接前提（编程手必须在输出前确认）

编程手在交付前，须确认以下工作已全部完成并记录：

- [ ] 所有子问题均已实现并运行通过。
- [ ] 验证记录已完善（跑通状态、与建模逻辑一致性、异常与修复说明）。
- [ ] 结果已导出为可交付论文手直接引用的文件（表格、数值、图表）。
- [ ] 图表文件按可视化规范生成并命名（含分辨率要求，如 PNG 600 dpi）。
- [ ] 题目要求追踪矩阵已在编程结果层面补齐证据列。

## 3. 交付论文手的责任边界

交付论文手须清楚自己的责任边界如下（不可将这些责任推回）：

- [ ] 正文写作所需的图表均由编程手产出，若需新增图表须在正文中明确标注并请求补充。
- [ ] 正文引用数据须以编程手提供的「结果文件清单」为准，不得擅自改写数值。
- [ ] 发现正文与编程结果存在偏差时，须在文档中留痕并请求编程手确认或修正。
- [ ] 正文用的术语须沿用编程手与建模手约定的术语表，未经讨论不得自创术语。
- [ ] 正文格式、排版、摘要、问题重述等不属于本契约范围，由交付论文手自行主导。

---

## 5. 回退触发点

当出现以下情况时，交付论文手须停止整理并转交回编程手（必要时再转交建模分析与审查/建模手）：

| 触发情况 | 交付论文手须做的事 | 转交对象 |
|---------|------------------|---------|
| 关键结果文件缺失或打不开 | 记录文件编号，要求补充 | 编程手核心 |
| 图表无法支撑正文对应论点 | 列出需要新增/重制图 | 编程手核心 |
| 结果数值与正文引用存在明显矛盾 | 标记偏差位置，请求核实 | 编程手核心 |
| 术语不一致导致正文指向歧义 | 给出对照并请求确认术语表 | 编程手核心 |
| 附录或正文发现有与内部数据冲突 | 标记冲突点，请求评审 | 编程手核心 → 建模分析与审查 |

---

## 6. 复核节点

在以下里程碑节点，建议三方同步（时间充裕时强制，时间不足时留痕）：

- [ ] 编程手完成全面验证之后
- [ ] 所有图表生成之后
- [ ] 正文初稿完成、准备排版之前
