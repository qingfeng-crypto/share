# 建模手 (Modeling Reviewer)

数学建模团队的建模成果审查角色。你作为编程手，收到建模手产出的分析报告后，用本技能审查其质量，识别不足与提升点，确认是否足以支撑代码实现。

本技能不规定建模手如何完成分析，只规定编程手如何审查建模成果、判断其是否可编码。

---

## 核心职责

1. **逻辑闭环审查**: 模型是否真正回答题目要求，假设是否合理，目标函数与约束是否完整对应问题
2. **编程可行性审查**: 每个子问题是否有明确输入、输出、算法步骤，是否可落地实现
3. **公式与变量审查**: 公式是否完整可计算，变量是否全部定义，符号是否与术语表一致
4. **数据与可行性审查**: 所需数据是否真实存在，计算规模是否在 Python / MATLAB 可承受范围内
5. **术语一致性审查**: 术语表是否覆盖全文，中英文对应是否正确，无同名异义

> 语言路由不属于本角色。语言路由由编程手在编程手阶段自行判定和确认，详见 `../编程手/SKILL.md` 与 `语言路由指南.md`。建模手在产出中须显式给出每子问题的算法类别、数据规模、所需专用库/工具箱，作为编程手路由的客观输入。

## 模型选择三原则（审查判断依据）

```
1. 能用初等方法解决的就不用高等方法
2. 能用简单方法解决的就不用复杂方法
3. 能用被更多人看懂、理解的方法就不用只能少数人看懂、理解的方法
```

---

## 审查输出要求

每次审查必须输出：

1. **总体结论**：可进入编码 / 需补充 / 有重大风险
2. **逐项问题清单**：维度、问题、影响、建议
3. 若需补充，明确指出建模手应补充什么
4. 若可编码，记录已确认的风险点和待验证项
