# 建模成果审查流程 (Review Workflow)

本文件供**编程手**审查建模手交付物时遵循。建模手不在此阶段执行分析，只产出分析报告、术语表与路由客观输入；编程手据此逐项审查，判断是否可以进入代码实现。

---

## 工具使用（审查时可用于核验）

### 一、pdf skill - 核验题目与参考论文

```python
import pdfplumber

with pdfplumber.open("题目.pdf") as pdf:
    for page in pdf.pages:

# 提取PDF中的表格
with pdfplumber.open("题目.pdf") as pdf:
```

## 审查流程

### 第零步：交付物完整性检查（必须最先执行）

检查建模手是否已交付以下文件，缺一不可进入审查：

- `题目分析.md`：问题分析、模型选择、算法设计、数据要求、参考文献
- `术语表格.md`：中英文术语对照、符号定义
- **路由客观输入**：每个子问题的算法类别、数据规模、所需专用库 / 工具箱

**缺失任一交付物** → 退回建模手补充，记录缺口。

### 第一步：题目理解核对

核对分析报告是否覆盖：

| 信息类型 | 审查要点 |
|---------|---------|
| 问题背景 | 背景与场景是否描述准确 |
| 问题类型 | 优化 / 预测 / 评价 / 分类判断是否合理 |
| 数据情况 | 已知 / 待求 / 数据特点是否清晰 |
| 约束条件 | 限制与边界是否完整 |
| 目标要求 | 需解决的具体问题是否明确 |

### 第二步：模型选择审查

**在审查模型选择时，必须核对分析文档中是否已记录对应论文的标题、作者、年份、来源。**

**防冗余原则（必须审查）**：
- 每个模型是否承载独特且不可替代的分析维度
- 模型之间是否形成互补证据链，而非重复验证同一结论
- 若两模型输出揭示同一层面信息，应判定冗余

#### 模型类型审查

| 问题类型 | 应出现的模型 |
|---------|---------|
| 优化问题 | 线性/整数/非线性规划、多目标规划、动态规划、图论模型 |
| 预测问题 | 时间序列分析、回归分析、灰色预测、神经网络（谨慎使用） |
| 评价问题 | AHP、熵权法、TOPSIS、模糊综合评价 |
| 分类问题 | 聚类分析、判别分析、支持向量机 |

### 第三步：编程可行性审查（替代原语言路由选择）

本步骤**不做语言路由**（路由由编程手在编程手阶段判定）。此处只审查：

1. 每个子问题是否有明确输入 / 输出 / 算法步骤，可落地实现
2. 路由客观输入是否齐全：算法类别、数据规模、所需专用库 / 工具箱
3. 若路由客观输入缺失，退回建模手补充，不得由编程手凭空假设

> 语言路由表由编程手建立，依据见 `语言路由指南.md`。

### 第四步：算法设计审查

1. **求解思路**：步骤是否完整、可复现
2. **算法流程**：是否有清晰流程或伪代码
3. **评价指标**：模型好坏的评判标准是否定义
4. **参数设置**：关键参数取值范围与调整方法是否给出

### 第五步：术语规范审查

核对术语表是否：

1. 覆盖题目与分析过程中的所有专业术语
2. 统一定义并给出明确中文定义
3. 提供标准英文翻译
4. 统一数学符号使用
5. 与分析报告中的符号完全一致

## 交付物缺口处理规则

审查中发现建模交付物不足时，按以下规则处理：

### 规则一：数据不足

| 场景 | 处理方式 |
|------|---------|
| 题目没给具体数据 | 退回建模手确认是否符号参数建模，标注"需实际数据代入" |
| 数据含大量缺失值 | 审查插补率，>30% 时要求建模手在论文中说明局限性 |
| 数据规模太小（<10条） | 核对是否选用灰色预测、参数检验等小样本方法 |
| 数据只有宏观总量 | 核对比例分配或假设分布的合理性 |

### 规则二：模型不适用

| 场景 | 处理方式 |
|------|---------|
| 首选模型假设不成立 | 要求建模手记录原因并说明备选方案 |
| 所有标准模型不完全匹配 | 核对是否组合 2-3 个模型分阶段求解 |
| 题目是交叉领域 | 核对是否已拆分为多子问题，各自最匹配模型 |
| 计算资源超出合理范围 | 要求建模手说明精度/简化取舍 |

### 规则三：问题类型不明确

按以下决策树判断建模手分类是否合理：

```
题目描述更偏"找到最佳方案"？                    → 优化类
题目描述更偏"推测未来趋势"？                    → 预测类
题目描述更偏"比较多个选项"？                    → 评价类
题目描述更偏"发现数据中的模式"？                → 分类/聚类
同时涉及以上多种？                              → 组合类，拆分子问题
```

### 规则四：不确定性处理

- **数据有噪声**：建模手是否引入鲁棒性考量、灵敏度分析
- **参数不确定**：是否做区间估计而非点估计
- **模型不确定**：是否用多模型交叉验证对比
- **假设有争议**：是否显式列出每个假设并说明违反后果

### 规则五：何时退回建模手

**必须退回补充的情况**：
- 路由客观输入缺失（算法类别 / 数据规模 / 所需库）
- 题目有多个理解方向且建模手未说明取舍
- 需要做比"合理假设"更强的约束性假设

**可直接进入编码的情况**：
- 缺失输入可由已有数据推导，且建模手已记录推导
- 通用参数默认值（如交叉概率 0.8、显著性水平 0.05）
- 标准建模流程选择（如先预处理再建模）

> **核心原则**：能做合理假设的不要退回，但所有假设必须已记录在分析文档中。

## 模型选择三原则（审查判断依据）

| 原则 | 说明 |
|------|------|
| **高效性** | 优先选择计算速度快、效率高的模型 |
| **准确性** | 确保模型能够准确描述和解决问题 |
| **简洁性** | 在满足要求的前提下，选择相对简单的模型 |
| **创新性** | 避免选择过于常见、使用人数过多的简单模型 |
| **实用性** | 尽量避免使用需要长时间训练的复杂模型 |

**谨慎使用的模型**：神经网络（仅在传统方法效果不佳时）、机器学习模型（优先尝试传统模型）、深度学习模型（仅在处理复杂高维数据时）

## 审查记录模板

每次审查产出独立的 `审查记录.md`，包含以下章节：

```markdown
## 一、审查结论
### 1.1 总体结论：可进入编码 / 需补充 / 有重大风险
### 1.2 已确认风险点
### 1.3 待验证项

## 二、逐项问题清单
| 维度 | 问题 | 影响 | 建议 |
|------|------|------|------|

## 三、退回补充项（如有）
- [子问题/交付物]：需建模手补充 [具体内容]

## 四、路由客观输入确认
| 子问题 | 算法类别 | 数据规模 | 所需库/工具箱 | 是否齐全 |
|-------|---------|---------|-------------|---------|
```
