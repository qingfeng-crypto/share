# 00_交付说明模板

以下内容用于生成 `00_交付说明.docx`。这是一份给论文手优先阅读的交接说明，不是正式论文正文。

## 1. 交付基本信息

```text
交付论文手说明
题目：[填写题目名称]
交付时间：YYYY-MM-DD HH:MM
交付角色：编程手核心
对应建模审查结论：[填写结论]
```

## 2. 本次交付包含内容

列出本次交付包包含的总览摘要、模型方法、结果表格、图表材料、代码与结果对应、可信度与验证、写作提示等内容。

必须明确说明：本交付包为论文写作中间材料，不是最终比赛提交文件；默认不回写项目目录，不参与 git。

## 3. 建议阅读顺序

建议阅读顺序：

1. `01_总览摘要/题目总体结论.md`
2. `01_总览摘要/子问题结论摘要.md`
3. `04_图表材料/图表清单.md`
4. `04_图表材料/每张图一句话结论.md`
5. `03_结果表格/结果表格清单.md`
6. `06_可信度与验证/结果可信度说明.md`

## 4. 可直接写入论文的内容

列出哪些结论句、表格、图表和方法说明可以直接改写进入论文，哪些更适合作为内部参考。

## 5. 必须谨慎表述的内容

至少提醒以下风险：

1. 假设较强的结论
2. 数值波动较大的结论
3. 仅观察到但未严格证明的现象
4. 异常值、边界情况、样本不足导致的局部结论

## 6. 图表与表格使用提示

说明哪些图适合正文结果分析，哪些图适合模型检验或讨论；哪些表适合正文主表，哪些表更适合附录。

## 7. 编程手特别提醒

至少保留以下手工填写项：

1. 本次结果中最重要的主结论
2. 本次最需要解释的异常或局限性
3. 本次最容易写错的地方

## 8. 文件版本与追溯说明

记录以下来源：

- 建模审查报告版本
- 本轮代码结果版本
- 图表版本
- 结果表版本

若论文手发现结论、表格、图表之间不一致，应优先回看 `05_代码与结果对应/文件来源说明.md`。
