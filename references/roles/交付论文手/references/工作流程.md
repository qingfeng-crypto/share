# 交付论文手工作流程

## 目标

把编程阶段已经产出的成果整理成论文手可直接接收的桌面交付包。

这一步是中间交接，不是论文正文写作，也不是重新求解。

## 默认桌面产出位置

默认保存目录：`C:\Users\qingf\Desktop\交付论文手_YYYYMMDD_HHMM\`

该目录中的内容属于中间交接物：

- 不回写项目目录
- 不参与 git
- 不作为正式比赛最终提交物

## 工作顺序

1. 收集上游已确认材料：建模主线、结果表、图表、验证记录、异常说明。
2. 先整理总览摘要，确保论文手先看到整体结论与风险。
3. 再整理模型与方法说明，只保留最终采用路线和必要公式变量。
4. 归档结果表格和图表材料，并补全每张图的一句话结论。
5. 整理代码与结果文件对应关系，保证论文手需要追溯时能定位来源。
6. 整理可信度、验证、异常点与局限性说明。
7. 最后填写 `00_交付说明.docx`，作为交付包入口。

## 处理边界

- 不重跑代码
- 不补做新的敏感性分析
- 不重做建模审查
- 不新增模型、算法或新的解释路线
- 只对已有成果做整理、归类、说明和风险标注

## 发现冲突时的处理

如果结果表、图表、结论摘要之间存在冲突：

1. 先记录冲突文件与冲突位置。
2. 在交付说明中标记该问题需要上游确认。
3. 不自行修改原始结论口径。

## 完成标准

完成交付前，至少确认：

1. 9 项固定输出清单已经齐全。
2. 桌面目录结构已经完整建立。
3. `00_交付说明.docx` 已按固定模板填写。
4. 已明确写出该交付包属于中间物，不回写项目目录，不参与 git。
