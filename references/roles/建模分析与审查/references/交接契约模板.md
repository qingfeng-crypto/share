# 交接契约 (Handoff Contract) — 建模分析与审查 → 编程手核心

本文件定义从 `建模分析与审查` 向 `编程手核心` 移交的桥梁契约，明确双方责任边界、接受内容、约定条件和复审触发点。

---

## 1. 交接前确认前提

编程手在接收本契约之前，须确认：

- [ ] 已阅读 `建模分析与审查/SKILL.md`，理解本契约只作为可选风险辅助，不强制阻塞进入编程。
- [ ] 已阅读 `编程手核心/SKILL.md`，理解路由与实现要求。
- [ ] 已阅读 `references/roles/建模分析与审查/references/语言路由指南.md`（或相关约定），了解路由由编程手独立判定。

> **重要**：语言路由由编程手自行判定并独立负责，下表「路由客观输入」仅为建模手提供的客观参考，编程手须审查其正确性与完整性，不得无条件接受。

---

## 2. 可进入编程的条件（建模分析与审查承诺）

建模分析与审查须在此明确放行条件：

| 条件 | 状态 | 备注 |
|------|------|------|
| 核心结论已清晰表述 | 已满足 / 待补 / 不适用 |  |
| 子问题拆解已完成 | 已满足 / 待补 / 不适用 |  |
| 关键公式已完整给出 | 已满足 / 待补 / 不适用 |  |
| 变量（含符号与单位）已全部定义 | 已满足 / 待补 / 不适用 |  |
| 所需数据可获取或已提供 | 已满足 / 待补 / 不适用 |  |
| 题目要求追踪矩阵已覆盖 | 已满足 / 待补 / 不适用 |  |
| 术语表（中英文）已校对 | 已满足 / 待补 / 不适用 |  |
| 阻断项全部已关闭或明确留风险给编程手 | 已满足 / 部分 / 不适用 |  |

- **绿灯结论**：以上全部「已满足」，可直接进入编程。
- **黄灯结论**：存在「待补」或「部分」项，但已记录放行条件；编程手可基于用户授权进入，但须追踪待补项。

---

## 3. 编程手必须独立确认的事项

编程手在接受本契约后，须独立完成并记录以下事项：

| 独立确认项 | 确认方式 | 确认结果 | 备注 |
|-----------|---------|---------|------|
| 方法-语言路由表已建立 | 建立路由前能力与环境预检 | 通过 / 未通过 |  |
| Python/MATLAB 候选求解器能力核验 | 官方文档或最小可运行示例 | 通过 / 未通过 |  |
| 最优性/可行性证明所需求解器是否可用 | 求解器主动核验 | 通过 / 不适用 | 仅对优化/NLP/MINLP 等 |
| 数据规模是否可承受 | 预检或小规模试跑 | 通过 / 未通过 |  |
| 建模手提供的路由客观输入是否正确 | 与路由表对照 | 正确 / 有误 |  |

> 若以上任一项未通过，须在实现前记录并决定是否回退给建模分析与审查或要求建模手补充。

---

## 4. 编程手的责任边界

进入编程后，编程手须清楚自己的责任边界如下（不可将这些责任推回）：

- [ ] 对话过程中产生的 bug 由编程手自行定位修复。
- [ ] 代码与模型的匹配性异常由编程手自行核验并修正。
- [ ] 第三方库 / 求解器报错由编程手独立排查或更换方案。
- [ ] 运行失败（异常退出/无输出）由编程手负责重跑、断点定位和错误恢复。
- [ ] 运行成功但与建模逻辑不一致（结果不合理）由编程手自行验证、回查输入和算法实现。
- [ ] 若发现此前建模结论与编程结果冲突，须将冲突证据收集完毕后交由建模手/建模分析与审查重新改模，编程手不可自行替换模型逻辑。

## 6. 交付物清单（编程手向交付论文手输出时）

编程手实现完成后，须整理如下输出供给交付论文手：

- [ ] 方法-语言路由表（含求解器版本及核验来源）
- [ ] 代码文件清单（路径、功能、依赖说明）
- [ ] 结果文件清单（路径、内容摘要）
- [ ] 图表文件清单（路径、用途、分辨率）
- [ ] 逐子问题最终结果（数值结论、置信区间或灵敏度说明）
- [ ] 验证记录（跑通状态、与建模逻辑一致性、异常说明、是否需回退建模分析与审查）

---

## 7. 意外与回退触发点

当出现以下情况时，编程手须停止实现并转交回建模分析与审查：

| 触发情况 | 编程手须做的事 | 转交对象 |
|---------|--------------|---------|
| 模型公式有误或缺少关键参数 | 收集冲突证据，说明具体位置与疑点 | 建模分析与审查 / 建模手 |
| 数据实际缺失且无法填补 | 记录缺失项与影响范围 | 建模分析与审查 |
| 题目要求与建模响应之间存在无法弥合的偏差 | 逐条比对证据后提出 | 建模分析与审查 |
| 求解器不支持，且无可行替代方案 | 列出候选并记录失败原因 | 建模分析与审查 |
| 运行结果与建模结论严重不符，且无法确定责任方 | 并列列建模假设与代码实现 | 建模分析与审查 + 建模手 |

---

## 8. 复核节点

在以下里程碑节点，建议双方或三方参与简短复核（时间充裕时强制，时间不足时编程手须记录）：

- [ ] 路由表建立之后、编码之前
- [ ] 最小功能尝试验证之后
- [ ] 所有子问题结果产出之后
- [ ] 实现结果与建模建议存在分歧时
